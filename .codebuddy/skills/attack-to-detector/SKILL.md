## 阶段1: 交易数据采集

### 目标
从 Phalcon Explorer 采集攻击交易的完整数据：调用链、事件日志、资金流向、余额变化。

### 操作步骤

1. **构造 URL 并访问**: 使用 Playwright MCP 的 `browser_navigate` 访问 `https://app.blocksec.com/phalcon/explorer/tx/{chain}/{tx_hash}`
2. **获取页面快照**: 使用 `browser_snapshot` 获取 Accessibility Tree 数据
3. **采集关键数据**:
   - **Overview 区域**: tx hash, block, timestamp, status, from/to, value, gas
   - **Balance Changes 表**: 所有地址的代币余额变化
   - **Invocation Flow**: 展开关键调用节点，获取完整函数调用链
   - **Fund Flow**: 资金流向图（代币 + 数量 + 方向）
   - **Event Logs**: 事件日志列表
4. **展开内部调用**: 对 flashLoan 回调、核心攻击逻辑节点，使用 `browser_click` 展开后再 `browser_snapshot`
5. **整理数据**: 将采集到的数据整理为结构化格式，用于后续分析

### 数据采集清单

| 数据类型 | 来源区域 | 用途 |
|----------|----------|------|
| 基础交易信息 | Overview | 报告头部、攻击者地址 |
| 余额变化 | Balance Changes | 资金流向分析、ROI计算 |
| 调用链 | Invocation Flow | 攻击步骤还原、函数级分析 |
| 资金流向 | Fund Flow | 资金流向图绘制 |
| 事件日志 | Event Logs | 通用特征提取（不依赖函数签名） |

### 质量门禁
- [x] 攻击者 EOA 地址已确认
- [x] 攻击合约地址已确认
- [x] 至少获取了 Balance Changes 和 Fund Flow
- [x] 核心攻击逻辑的调用链已展开

## 阶段2: 撰写攻击分析报告

### 目标
基于采集的数据，按照标准报告模板撰写分析报告，提炼通用检测特征。

### 报告存放路径
`docs/攻击事件分析驱动检测器开发/{项目名}/{项目名}攻击分析-通用检测特征.md`

### 报告标准结构

参考 `references/report-template.md` 获取完整的报告模板。核心章节:

1. **攻击概述** — 攻击本质、类型分类、损失金额
2. **资金流向** — 完整的资金流向图 + 投入产出表
3. **通用攻击特征（不依赖函数签名）** — 核心章节，每条特征包含:
   - 定义
   - 本交易表现（具体数据）
   - 检测方法（伪代码）
   - 通用性说明
4. **特征组合与评分矩阵** — 特征组合 → 评分映射
5. **与现有检测器的覆盖度分析** — 逐检测器分析覆盖和缺口
6. **检测器扩展建议** — P0/P1/P2 优先级排序
7. **关键地址** — 攻击涉及的所有地址
8. **关键事件日志索引** — 事件索引表
9. **总结** — 核心发现 + 最小可行扩展路径

### 特征提炼原则

- **不依赖函数签名**: 所有特征从资金流、事件日志、地址关系中提取
- **可检测性**: 每条特征必须有明确的检测方法（伪代码）
- **通用性**: 说明特征在不同协议/链上的适用性
- **组合性**: 特征可组合，组合后评分非线性叠加

### 质量门禁
- [x] 至少提炼 5 条通用攻击特征
- [x] 每条特征有检测方法伪代码
- [x] 特征组合评分矩阵完整
- [x] 现有检测器覆盖度分析完整
- [x] 检测器扩展建议有优先级排序

## 阶段3: 检测器节点开发

### 目标
根据分析报告中的检测器扩展建议，开发新的检测器节点或增强现有检测器。

### 检测器架构参考

参考 `references/detector-architecture.md` 了解:
- 检测器节点的类继承体系
- 配置/输入/输出模型定义
- 注册机制
- 前端节点面板集成

### 开发流程

1. **确定开发目标**: 从报告的检测器扩展建议中选择 P0/P1 优先级的检测器
2. **选择增强或新建**:
   - **增强**: 在现有检测器中添加新的检测维度
   - **新建**: 创建新的检测器节点文件
3. **实现检测逻辑**:
   - 继承 `BaseDetector`（节点层）或 `BaseBehaviorDetector`（trace层）
   - 实现 `process()` 方法
   - 使用标准 ERC-20 Transfer / DEX Swap 事件 topic，不依赖函数签名
4. **注册节点**: 在 `nodes/detectors/__init__.py` 中注册新检测器
5. **前端集成**: 在 `frontend/src/api/nodeSchema.js` 中添加节点 schema，在 `NodePalette.vue` 中确保分类显示

### 关键编码规范

- 使用 `.venv\Scripts\python.exe` 执行 Python
- 不吞异常，保留完整异常链（`raise ... from e`）
- 缩进一致性：修改时对比相邻函数的缩进层级
- UTF-8 编码：读写含中文的文件必须指定 `encoding='utf-8'`
- 每次修改 `.py` 后验证缩进

### 质量门禁
- [x] 检测器可正常导入和实例化
- [x] `process()` 方法逻辑完整
- [x] 在 `__init__.py` 中已注册
- [x] 前端 nodeSchema.js 已更新（如需要）

## 阶段4: 重复检测器合并/增强

### 目标
检查新开发的检测器是否与现有检测器功能重叠，如有则合并增强而非重复实现。

### 操作步骤

1. **扫描现有检测器**: 读取 `nodes/detectors/` 下所有检测器源码，了解每个检测器的检测维度
2. **比对检测维度**: 将新检测器的检测维度与每个现有检测器比对
3. **判断重叠**:
   - **高重叠** (>60% 维度相同): 合并到现有检测器中增强
   - **中重叠** (30-60%): 保留独立检测器，但共享工具函数
   - **低重叠** (<30%): 保持独立，无需合并
4. **执行合并**: 如需合并:
   - 将新检测维度添加到现有检测器的 `process()` 方法
   - 更新评分逻辑（基础分 + 组合加分）
   - 删除独立的新检测器文件
   - 更新 `__init__.py` 注册

### 合并判断标准

| 场景 | 处理方式 |
|------|----------|
| 新检测器是现有检测器的子集 | 合并到现有检测器 |
| 新检测器与现有检测器有部分重叠 | 合并重叠部分，保留独立部分 |
| 新检测器完全独立 | 保留为独立检测器 |
| 两个检测器检测同一攻击的不同阶段 | 保持独立，文档中标注协作关系 |

### 质量门禁
- [x] 所有现有检测器的功能已审查
- [x] 重叠检测维度已识别
- [x] 合并/独立决策已记录
- [x] 合并后的检测器逻辑正确

## 阶段5: 测试

### 目标
为所有新增和修改的检测器编写单元测试，确保功能正确。

### 操作步骤

1. **创建测试文件**: 在 `tests/nodes/` 下创建 `test_{detector_name}.py`
2. **编写测试用例**:
   - **正常检测测试**: 构造模拟攻击日志数据，验证检测器能正确检测并评分
   - **阴性测试**: 构造正常交易数据，验证检测器不误报
   - **边界测试**: 验证阈值边界、零值、空输入等
   - **组合特征测试**: 验证特征组合评分的逻辑
3. **运行测试**: 使用 `.venv\Scripts\python.exe -m pytest tests/nodes/test_{detector_name}.py -v` 运行
4. **修复问题**: 如测试失败，修复代码后重新运行直到全部通过

### 测试数据构造

参考现有测试文件中模拟日志的构造方式:
- 使用标准 ERC-20 Transfer 事件 topic (`0xddf252ad...`)
- 使用 Uniswap V2/V3 Swap 事件 topic
- 构造 `TransactionContext` 对象传入检测器

### 质量门禁
- [x] 所有新增函数有测试覆盖
- [x] 所有测试通过
- [x] 阴性测试存在（验证无误报）
- [x] 边界条件已测试

## 阶段6: Git 提交

### 目标
将完成的阶段性工作提交到 Git，便于后续回退。

### 操作步骤

1. **检查变更**: `git status` 查看所有修改的文件
2. **检查敏感数据**: 确认没有 API key、密码等敏感数据
3. **暂存文件**: `git add` 添加相关文件（排除临时文件、`.pyc`、数据库文件等）
4. **提交**: `git commit -m "feat: {描述本次工作内容}"`，使用约定式提交格式

### 提交信息格式

```
feat: 添加 {攻击名称} 攻击分析报告 + {检测器名称} 检测器

- 添加 {攻击名称} 攻击交易分析报告
- 新增/增强 {检测器名称} 检测器
- 检测维度: {列出主要检测维度}
- 测试: {测试文件数量} 个测试全部通过
```

## 通用注意事项

1. **虚拟环境**: 所有 Python 命令必须使用 `.venv\Scripts\python.exe`
2. **编码**: 含中文的文件读写必须指定 `encoding='utf-8'`
3. **异常处理**: 禁止裸 `except`，保留异常链 `raise ... from e`
4. **临时文件**: 调试脚本使用后立即删除，不提交到 Git
5. **文档更新**: 完成后更新 README.md 或 docs 下的相关文档
6. **缓存清理**: 修改源码后提醒清理 `__pycache__`
